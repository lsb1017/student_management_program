# 학원 성적·학생 관리 통합 프로그램

만두OMR 1.0.6(2026-10-25)의 채점·인식·성적표 코드를 이식하고 오답 관리·성적표 열람 웹·카카오톡 안내·손풀이 삽입·Google Drive 이어받기를 더한 Windows 데스크톱 프로그램임. 설계 기준은 `ARCHITECTURE.md`(2026-11-01)임. 기존 만두OMR 실행 파일과 데이터 폴더는 쓰지 않음.

## 설치와 실행

Windows 10/11, Python 3.12 **x64**가 필요함. Windows on ARM PC에서도 x64 Python을 써야 함(OpenCV에 ARM64 휠이 없음).

```powershell
py -3.12 -m venv .venv                       # 저장소 루트
.\.venv\Scripts\python.exe -m pip install -r manduomr\requirements-dev.txt
cd manduomr
..\.venv\Scripts\python.exe main.py                               # 데이터: 저장소 루트의 data\
..\.venv\Scripts\python.exe main.py --data-dir D:\학원자료
..\.venv\Scripts\python.exe main.py --simulate-drive D:\가상드라이브   # Google 계정 없이 시험 운영
```

`--simulate-drive`는 Google Drive 대신 지정 폴더를 백업 폴더로 씀. PC 여러 대가 같은 공유 폴더를 가리키면 잠금·이어받기를 Drive 없이 시험해 볼 수 있음. 실제 운영은 시작 화면의 '백업 폴더 설정 → Google Drive 폴더 연결'로 함.

## 처음 설정 순서

1. 시작 화면에서 백업 폴더를 연결함. Google 로그인은 1.0.6과 같은 브라우저 PKCE 방식이며 토큰은 Windows DPAPI로 암호화해 PC별로 둠.
2. 작업자·작업 학원을 입력하고 시작함. 작업 학원은 백업 파일명(`날짜_시간_학원명.omrbackup`)에만 쓰이고 백업은 전체 자료임.
3. 1.0.6 자료를 쓸 경우 빈 자료 상태에서 홈의 '1.0.6 자료 가져오기(1회)'를 실행함(아래 이관 참고).
4. 학생·분반: 분반을 학원·요일로 만들고(예: 청솔(토)) 학생을 등록함. 학번이 발급되면 안내 여부를 물음.
5. 시험·양식: 주간지 OMR 양식을 만들어 PDF로 인쇄하거나, 이미 쓰는 양식을 빈 양식 스캔 위 좌표로 등록함. 시험을 등록하고 문항 정보 엑셀(1.0.6 서식)을 가져옴.
6. 설정: 열람 웹 주소, 성적표 게시 폴더(비공개), 카카오 채널 식별자, 발송 방식을 입력하고 신규생 안내문을 등록함.
7. 열람 웹을 배포함(아래 순서).

## Google Drive 백업·실행 잠금

Drive 백업 폴더는 `*.omrbackup`(전체 자료), `files/`(파일함, 같은 해시는 한 번만 올림), `locks/`(실행 잠금)로 구성됨. Drive에는 원자적 잠금이 없으므로 잠금 파일을 만든 뒤 목록을 다시 읽어 Drive가 매긴 생성 시각이 가장 이른 PC만 진행함.

| 상황 | 동작 |
| --- | --- |
| 다른 PC가 잠금 보유 | 실행 불가 안내(작업자·시작 시각), 관리자 강제 해제 가능(미업로드 변경 미반영 경고·사유 기록) |
| 시작 시 Drive 연결 실패 | 실행하지 않음. 이 PC가 잠금을 보유한 경우에만 오프라인 작업 허용 |
| 올리지 못한 변경이 남은 채 시작 | 내려받기 전에 먼저 업로드 |
| 최신 백업 무결성·스키마 검사 실패 | 교체하지 않고 직전 백업 선택 화면 |
| 1.0.6 백업이 최신 백업으로 올라와 있음 | 교체하지 않음(이관 도구 안내) |
| 종료 시 변경 없음 | 새 백업 없이 잠금만 해제 |

잠금 보유·마지막 내려받기/올리기 정보는 DB가 아닌 `data/sync_state.json`에, PC 식별자와 백업 폴더는 `data/local.json`에 둠. 백업 복원으로 덮이지 않게 하기 위함임.

## 성적표 열람 웹 배포

1. 설정 화면의 '열람 웹 배포 파일 저장'으로 `Code.gs`, `index.html`, `appsscript.json`, `스크립트_속성.txt`를 받음.
2. 학원 Google 계정에서 Apps Script 새 프로젝트를 만들고 세 파일 내용을 붙여 넣음(편집기 설정에서 `appsscript.json` 표시).
3. 프로젝트 설정 → 스크립트 속성에 `ROOT_FOLDER_ID`, `PEPPER`, `FAIL_LIMIT`, `LOCK_MINUTES`를 넣음. `PEPPER`는 외부에 공유하지 않음.
4. 배포 → 새 배포 → 웹 앱, 실행 계정 '나', 액세스 '모든 사용자'로 배포하고 주소를 설정의 '성적표 열람 웹 주소'에 넣음.
5. 성적표 게시 폴더는 공유를 '제한됨'으로 둠. 열람 웹이 서버에서 학번·이름 해시를 확인한 파일만 읽어 전달함.

링크 형식은 회차 안내 `주소?s=회차키`, 신규생 안내문 `주소?n=안내문키`임. 회차 키 없이 들어오면 그 학생의 가장 최근 성적표를 보여 줌. 같은 학번으로 5회 연속 실패하면 10분간 잠김.

## 카카오톡 안내

카카오비즈니스 파트너센터에는 발송 API가 없어 Playwright로 Windows 기본 Edge를 조작함. 화면 조작 순서와 선택자는 `academy/adapters/kakao/selectors.json`에 있어 화면이 바뀌면 이 파일만 고침.

- 최초 1회 담당자가 열린 창에서 로그인·2단계 인증함. 이후 `data/kakao_profile` 세션을 재사용하며 비밀번호는 저장하지 않음.
- 분반 회차 안내: 채널 메시지(기본 텍스트형 + 성적표 보기 버튼). 20:55~08:00에는 다음 날(또는 당일) 08:00 예약 발송으로 등록함. 같은 회차는 1회만 보내며 재발송은 확인창을 거침.
- 신규생 학번 안내: 사용자 결정(2026-11-01)에 따라 알림톡 API 대신 채널 화면 자동화로 보냄. 친구그룹 종료·타게팅 11명 이상 제한 때문에 한 학생만 고르는 채널 메시지는 보낼 수 없으므로, 학생·학부모가 채널에 먼저 말을 건 1:1 채팅방에서 보냄. 검색 결과가 정확히 1개일 때만 보냄.
- 자동화가 멈추면 문구·링크·대상 명단을 띄워 담당자가 직접 보내고 '수동 발송 완료'로 기록함. 설정에서 발송 방식을 '수동 발송'으로 두면 항상 이 창을 띄움.
- 설정의 '자동화 시험 실행'을 켜면 발송 버튼 직전에서 멈춰 선택자를 확인할 수 있음.

## 1.0.6 자료 이관

홈의 '1.0.6 자료 가져오기(1회)'는 1.0.6 최신 백업(데이터 구조 10)을 빈 자료로 1회 변환함.

- 학생·시험·답안 내부 ID를 유지해 성적·답안 연결이 바뀌지 않음.
- 모든 학생에게 7자리 학번을 새로 발급함. 기존 6자리 번호는 학번 이력과 성적 스냅샷의 `legacy_code`에 남김. 이관 학생은 성적표·안내 화면의 안내 대기 목록에 올라감.
- OMR 원본·스캔 이미지 BLOB은 파일함으로 옮김.
- 반 이름이 `청솔(토)`처럼 요일로 끝나면 요일을 채움. 수능수학 시험은 모의고사, 그 밖은 기타 유형이 됨.
- 이관 후 확정 답안을 다시 채점해 1.0.6 저장 점수와 하나라도 다르면 전체를 취소함.

## 데이터

- `data/academy.sqlite3`(WAL, 스키마 11): 1.0.6 스키마 10의 테이블에 신규 테이블 14개와 `student_codes`(학번 이력)·`file_objects`(파일함 목록)를 더함. `students.code`는 7자리, `classes.weekday`, `exams.exam_kind`·`form_id`, `audit.operator_id`가 추가됨.
- `data/files/<해시 앞 2자리>/<SHA-256>.<확장자>`: OMR 원본·스캔·한글 원본·문항·손풀이·결과 PDF. 한 번 쓴 파일은 수정하지 않음.
- `data/backups/`: `automatic`(자동 저장), `outgoing`(올린 백업), `incoming`(내려받은 백업), `before_restore_*`(교체 전 안전 백업).
