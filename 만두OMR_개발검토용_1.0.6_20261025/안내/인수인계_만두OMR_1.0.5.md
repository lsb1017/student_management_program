## 적용한 요청

1. 홈 ‘지금 백업’은 이름·저장 위치 팝업 없이 data/backups/automatic에 고유 파일명으로 저장하고 연결된 Drive에 업로드한다. 로컬 저장 완료와 업로드 완료를 구분한다. 파일 자동 삭제는 하지 않는다.
2. ‘다른 위치에 백업 저장’은 별도 버튼으로 제공한다. 기존 이름·경로 지정, 덮어쓰기 방지, 수기 미저장 보호와 작업 중 닫기 방지를 유지한다.
3. Drive 검색에서 앱 업로드 표식이 없는 수동 업로드 .omrbackup도 포함한다. 수정 시각 내림차순으로 최신 후보를 찾고, 다운로드 후 SQLite 백업 형식을 검사하며 사용자가 확인해야 복원한다. 최신 후보가 잘못된 백업이면 오류로 중단하며 무시하고 자동 복원하지 않는다.
4. 연결 설정은 안내창 없이 Google 로그인으로 연결한다. 폴더 입력창은 제거했다. DEFAULT_FOLDER=1k-MGOEQfrsNVxzah5iEPfgrAnEQhafHe. 저장된 기존 폴더가 있으면 그 값을 우선한다.
5. 연결됨은 연두색(#E5F3CE, 글씨 #3F6212), 미연결·연결 오류는 주황색(#FFE1BD, 글씨 #9A4508). 실패한 연결은 토큰이 존재해도 오류로 표시한다.
6. 공개 공유 요청은 취소됐다. 공유 권한은 변경하지 않았으며 제한됨 유지가 사용자 최종 결정이다. Google 로그인·승인 및 미검증 앱 경고 자체는 제거하지 않았다.

## 배포·연결 유의점

새 폴더에 배포하며 기존 실행 폴더를 덮어쓰지 않았다. ZIP에 사용자 DB·토큰·백업을 포함하지 않는다. 따라서 새 폴더에서는 Google 연결이 필요하지만 연결 안내창·주소 입력창은 없고 Google 로그인·승인만 수행한다. 기존 프로그램 최신 백업은 PC 백업 가져오기로 이관할 수 있다.

Google OAuth가 테스트 상태이면 재인증이 필요할 수 있다. 공개 링크로 바꿔도 업로드 인증은 없어지지 않는다. 사용자 계정 토큰을 소스나 배포 ZIP에 넣지 않는다.

Python 빌드 환경과 테스트 실행 방식은 1.0.4 문서 참조. 패키징 스크립트 work/package_105.py, smoke work/smoke_105_run.py, 화면 work/render_105.py. 새 배포 ZIP 해시와 크기는 work/package_105_result.json.

## 학생 합치기 확정 요청 (2026-10-24, 구현 대기)

- 학생 두 명을 선택하고 유지할 학생번호를 확인한 뒤 한 학생으로 합친다. 기존 성적·답안·OMR 연결과 모든 소속 반을 보존하며 과거 응시 당시 소속 정보는 유지한다.
- 삭제되지 않은 시험 기록이 두 학생에게 겹치면 아무것도 변경하지 않고 중단한다. 겹치는 시험 목록과 OMR 채점·검수에서 해당 OMR 행을 선택 행 삭제로 정리한 뒤 다시 시도하라는 안내를 표시한다. 시험 자체나 학생 등록을 삭제하라는 안내는 하지 않는다.
- 삭제 상태의 OMR 행은 합치기 중복 검사에서 제외한다. 확정·대기·제외·이전응시·수기·이관 성적의 실제 저장 구조를 검토하여 검사 대상과 예외를 구현 전 명확히 하고 숨은 기록 충돌을 검증한다.
- 실행 전 안전 백업을 생성하고 합치기는 단일 트랜잭션으로 처리한다. 실패 시 변경 전체를 되돌린다.
- 합친 학생의 삭제 기록과 기존 삭제 취소 이력도 추적한다. 삭제 취소 시 합친 학생과 시험 기준으로 충돌을 다시 검사하여 중복 성적을 생성하거나 기존 성적을 덮어쓰지 않도록 차단하고 사유를 안내한다. 과거 학생 식별자로 되살아나거나 연결이 끊기는 경우도 방지한다.
- 자동 병합하지 않는다. 현재 성적을 실제로 옮기거나 삭제하는 작업은 반영 시작! 이후 구현 및 검증 대상이다.

안내 예시: 같은 시험의 기록이 두 학생에게 등록되어 있어요. 겹치는 시험: [시험 목록]. OMR 채점·검수에서 남기지 않을 OMR 행을 선택 행 삭제한 뒤 다시 시도해 주세요. 시험 자체를 삭제할 필요는 없어요.

## 중복 등록 예방 요청 (2026-10-24, 구현 대기)

같은 학원에서 이름과 전화번호가 일치하는 기존 학생을 발견하면 새 학생 생성 전에 기존 학생에게 반을 추가할까요? 안내. 기존 학생 정보를 확인하고 사용자 선택으로 반 추가. 이름만으로 자동 연결/자동 병합하지 않음. 기존 반·성적 유지. 현재 중복 등록 안내와 통합해 중복 팝업 방지. 기존 이중 등록 성적을 자동 이전하는 기능과 구분.

## 학생 합치기 최신 조건 (2026-10-24, 구현 대기)

- 기존 보강생 연결의 학생 재연결 처리를 참고·재사용하되 그대로 호출하여 검수 대기로 바꾸지 않는다. 합치기 전 확정 상태와 답안·점수를 유지한다. 기존 검수 대기 기록은 자동 확정하지 않는다.
- 사용자는 반별 평균·석차 변경을 수용했다. 기존 details의 과거 소속 유지 조건은 최신 결정으로 대체: 유지할 학생의 기본 반 기준으로 성적 소속을 변경할 수 있으며 두 학생의 소속 반 연결은 보존한다.
- 수기 성적 합치기는 지원하지 않는다. 부분 이동으로 기록이 나뉘지 않도록 관련 수기 성적이 발견되면 아무 변경 없이 합치기를 중단하고 수기 성적이 있어 합칠 수 없다고 안내하는 범위로 정리한다.
- 겹치는 시험 중단·OMR 행 삭제 후 재시도 안내, 합친 뒤 삭제 취소 충돌 차단, 사전 안전 백업 및 트랜잭션 보장은 유지한다.

이 최신 조건은 앞선 과거 소속 보존 제안보다 우선한다. 사용자 반영 시작! 지시 전에는 구현하지 않는다.

## 학생 합치기 수기 성적 정책 최종 갱신 (2026-10-24, 구현 대기)

유지할 학생의 수기 성적은 보존하고, 옮길 학생의 수기 성적만 삭제한다. 삭제 전에 대상 학생·건수·시험 목록을 안내하고 취소 / 수기 성적 삭제 후 합치기 버튼으로 명시 동의를 받는다. 기본 선택 취소. 동의 후 안전 백업에 성공해야 삭제와 합치기를 하나의 트랜잭션으로 수행하며 실패하면 전체 롤백한다. 기존 무조건 중단 방침을 대체한다.

겹치는 시험도 같은 방식으로 처리할지는 아직 제안 검토 단계다. 사용자 확정 전에는 기존 중복 시험 중단 요구를 유지한다. 프로그램 코드는 아직 수정하지 않았다.

## 겹치는 시험 처리 최종 확정 (2026-10-24, 구현 대기)

- 유지할 학생의 기존 성적은 보존한다.
- 옮길 학생의 겹치는 시험 기록만 삭제하고, 겹치지 않는 OMR 기록은 기존 확정 상태·답안·점수를 유지하여 옮긴다.
- 삭제 전에 옮길 학생 및 유지할 학생을 명확히 표시하고 삭제 대상 시험명·점수 목록을 보여준다. 명시적으로 중복 기록 삭제 후 합치기를 선택해야 진행한다. 기본 선택은 취소이며 취소하면 아무 변경도 하지 않는다.
- 동의 후 삭제 전에 안전 백업 생성. 백업 실패 시 중단. 삭제 및 합치기를 단일 트랜잭션으로 처리하여 실패 시 전부 롤백. 합친 뒤 삭제 취소로 중복 성적이나 잘못된 학생 연결이 발생하지 않도록 차단한다.
- 겹치는 시험 발견 시 무조건 중단하고 기존 화면에서 삭제 후 재시도하도록 안내하던 이전 정책을 대체한다.
- 수기 성적은 기존 최신 정책대로 유지할 학생 기록은 보존하고 옮길 학생 기록만 사전 동의 후 삭제한다. 중복·수기 양쪽에 해당하는 삭제 대상은 중복 집계하지 않으며 최종 삭제 목록을 명확히 보여준다.

이 최신 확정은 앞선 중복 발견 시 중단 정책보다 우선한다. 현재 요청은 변경목록 기록이며 프로그램 구현·실데이터 변경은 하지 않는다.
