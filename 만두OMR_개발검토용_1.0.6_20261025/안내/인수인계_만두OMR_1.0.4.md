## Google Drive: 실제 계정 검증 완료

2026-10-23 실제 계정 인증, 지정 폴더 업로드, 다운로드 및 SHA256 일치를 확인했다. 학생·성적 0건인 검증용 백업만 사용했고 해당 원격 파일은 휴지통으로 이동했다. 결과: work/drive_live104_result.json. 실패 재시도 및 복원 보호 로직은 모의 응답 검사도 수행했다.

사용자가 데스크톱 OAuth JSON을 제공했고 `assets/google_client.json`으로 포함했다. 이 설정의 내용을 대화·로그에 출력하지 않는다. 접근/갱신 토큰은 배포물에 포함하지 않았다.

연결 폴더 ID: 1k-MGOEQfrsNVxzah5iEPfgrAnEQhafHe. 이 PC의 outputs/Windows_1.0.4/만두OMR/data/drive 에 암호화 토큰과 폴더 설정을 저장했다. 배포 ZIP에는 data 폴더를 포함하지 않으므로 새 압축 해제 폴더와 다른 PC에서는 연결해야 한다. 실사용 자료를 테스트 목적으로 변경하지 않았다. 인증 첫 시도는 테스트 사용자 미등록, 다음 시도는 3분 대기 만료로 실패했다. 등록 후 새 로그인은 정상 완료했다.

OAuth는 시스템 브라우저, 127.0.0.1 임시 포트, state 검증, PKCE S256을 사용한다. 기존 사용자가 만든 폴더를 직접 지정하는 방식이라 현재 scope는 전체 Drive 파일 접근이다. UI에서 권한을 설명한다. 프로그램의 조회는 지정 폴더 안의 `mandu_backup` 앱 속성이 있는 파일로 제한한다. `drive.file`로 줄이려면 Google Picker 등 별도 폴더 선택 권한 설계가 필요하며 현재 구현과 혼동하지 않는다.

토큰은 Windows DPAPI로 사용자 계정에 묶어 `data/drive/google_token.bin`에 암호화 저장한다. 설정과 대기 사본은 `data/drive`에 있다. 이 폴더와 토큰은 OMR 백업에 넣지 않는다. PC마다 연결해야 한다. 외부 OAuth 앱 테스트 상태의 갱신 토큰 만료 및 운영 게시 설정을 확인해야 한다.

편집마다 자동 업로드하는 구조는 아니다. 작업 후 ‘새 백업 저장’을 누르면 업로드가 자동 실행된다. 실행 시 최신 원격 백업을 확인하되 사용자 동의 없이 복원하지 않는다. 로컬 미백업 수정/초안/대기 업로드가 있으면 가져오기를 막고 보존을 안내한다. 복원 직전에도 변경 여부를 재확인한다. 복원은 기존 전체복원·안전백업 흐름을 이용한다.
